# ADR-0003: 配布と自動更新に Velopack を採用する

- ステータス: 承認済み
- 決定日: 2026-08-05
- 決定者: 中村勝

## 背景

「インストーラーを作成すること」「GitHub 上のバージョンが上がった場合は自動アップデートすること」
「更新は自動／手動／不要を設定可能とすること」が要件。
候補は Inno Setup + 自作更新、Velopack、MSIX、WiX(MSI) の4案。

## 決定

**Velopack** を採用する。インストーラー生成（vpk pack）と差分自動更新（UpdateManager + GithubSource）を
一体で利用し、リリースは GitHub Releases に配置する。

## 理由

- インストーラーと更新機構が同一ツールチェーンで完結し、自作更新ロジックの保守コストが不要。
- GitHub Releases をフィードとして標準サポートしており、要件「GitHub 上のバージョン検知」に直結する。
- ユーザー単位インストールが既定で、管理者権限なしにインストールできる（NFR-01）。
- MSIX はコード署名証明書が事実上必須で、現時点で未手配（ISS-001）のため見送り。
- WiX(MSI) は企業配布向けだが更新機構を自作する必要があり、要件に対して重い。

## 影響

- 更新モード「不要」の場合は UpdateManager を一切呼ばない実装とし、通信を完全に止める（FR-ST-07）。
- 更新確認は例外を握りつぶさずログに残しつつ、UI・アプリ動作へ波及させない（FR-ST-08）。
- リリース手順を GitHub Actions で自動化し、手順書を `docs/release.md` に記載する。
- コード署名なしのため SmartScreen 警告が出る。運用手順書で周知する（ISS-001）。
